# Validation and next development issues

The complete suite passes 67 tests using `python -m unittest discover -s tests -v`. Tests exercise independent hand-constructed events as well as the notebook's seed-42 regression examples. They verify event boundaries and player isolation, failed passes, geometric progression threshold, box entry, non-goal shots, empty windows, overlap, sequence denominators, evidence provenance, reproducible generation, reference self-comparison, nonfinite rejection, and story score suppression below the display threshold. Narrative and provider checks cover tampered claims, bilingual output, local fallback and simulated Microsoft responses. The original notebook JSON payload reproduces Alex's known `(28, 43]` selection: 14 sequences and 16 events.

These checks establish implementation behavior; they do not establish that the scoring model measures historical football similarity.

## Prioritized next issues

1. **Validate imported data at the analysis boundary.** Require unique nonempty event IDs; finite minutes and coordinates in range; booleans for completion; supported event types; nonempty player and sequence IDs. Define how a shared possession ID differs from a player action sequence. The current generated fixture is well formed, but arbitrary imported tables may produce misleading counts.
2. **Retain explicit sequence ownership across time windows.** The current app assigns each sequence to its initiating minute and excludes events after the replay cutoff. The preserved notebook engine uses selected-event attribution and can count a crossing sequence in adjacent windows. Keep that distinction explicit when comparing outputs.
3. **Separate normalized coordinates from physical distance.** The 25% goal-distance reduction, 30-unit long-pass threshold, and 50-unit lateral switch threshold are explicit prototype conventions. A square 0–100 calculation is not distance in metres on a rectangular pitch. Specify pitch dimensions before interpreting physical distances or comparing external data providers.
4. **Improve synthetic match coherence.** Existing independent action opportunities do not represent continuous two-team possessions, pass recipients, defensive actions, score state, or tracking. Add the schema and generator evidence needed for each new role before adding its scoring profile. An arrival record alone cannot establish an observed off-ball run from ordinary event data.
5. **Keep model scores independent and experimental.** Reference rates, weights, and scales are invented. Scores need not sum to 100, are not probabilities, and cannot establish authentic legend resemblance. Self-score 100 tests the formula only. The zero weight on box touches is tied to generator duplication; reassess that assumption if the generator changes.
6. **Evaluate sample size and sensitivity.** Ten sequences is a display rule, not demonstrated statistical confidence. Trials over multiple seeds and plausible weighting choices can measure score instability but do not validate historic references. Show sample counts and avoid definitive rankings of close scores.
7. **Evaluate live model integration.** The current validator checks exact measurement counts and evidence IDs and rejects arbitrary prose and extra claims. The optional Microsoft connector has simulated-transport verification only. Test a real deployment and assess useful claim selection, latency, cost and failure behavior while retaining the distinction between local fallback and accepted model selections.

The original three midfield profiles retain their original tests. The separate role expansion is reviewed below.

## Eight-role expansion review

A separate role engine now has eight analysis groups: goalkeeper, centre-back, full-back, CDM, CM, CAM, winger and striker. It uses five configured measures and three invented archetypes per role. The original notebook engine remains available and its regression tests remain unchanged. These two engines have different feature definitions and weighting; their scores must not be presented as directly interchangeable.

The role generator assigns 60 initiating action sequences to each of eight primary players. Additional synthetic receiver shots supply chance-creation evidence, and opposing shots support saves; these are evidence actors, not extra selectable players or additional opportunities. All rows retain `synthetic=True`. Defensive outcomes, normalized pass/carry geometry, tags, and follow-up shots are explicitly simulated; none is inferred from actual Premier League match data.

Role window ownership follows sequence start, with future events gated at the replay cutoff. Thus adjacent windows avoid double-counting a sequence, while a still-unfinished chance cannot use a later receiver shot. Chance evidence requires the same sequence, another player on the same team, and a shot at or after the pass; supporting receiver IDs are retained separately from the creator's own action IDs. This fixes a future-information issue discovered during review.

Tests cover role isolation, independent success/failure outcomes, valid/invalid chance and save evidence, replay cutoff, boundary attribution, source schemas, seed reproducibility, archetype self-scores, overlap denominators, and the 10-sequence display rule. These supplement rather than replace the original notebook tests. CAM through balls require explicit scenario tags, successful completion and forward travel; without defender tracking the tag is not independently validated.

Team-wide **role demonstration coverage** includes seven outfield groups plus a separate goalkeeper model. Ethan Vale supplies 60 synthetic goalkeeper sequences, five measures and three invented archetypes. Saves require an earlier opposing saved shot, with secondary evidence IDs; claims and sweeper interventions require explicit successful outcomes. All 24 role references pass self-comparison checks. The CAM dataset was redesigned for central creation; other existing player action values are preserved, although global event IDs change when new events are inserted.

This is not a complete 22-player match, authentic legend database, or validated historic similarity method. Legend names are design inspirations only. The principal next work remains coherent two-team possession generation, imported schema checks, historically supportable reference design, and live Microsoft inference evaluation. The optional model adapter has only simulated-transport verification so far.
